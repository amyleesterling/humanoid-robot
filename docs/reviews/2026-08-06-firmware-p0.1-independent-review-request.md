## Required review

1. Inspect every source, test, configuration and manifest row; independently reproduce all 17 tests and hashes.
2. Verify outputs default off, three valid heartbeat edges are required before KWD commands, stale/too-fast/invalid feedback faults drop both channels, and diagnostic faults cannot be cleared online.
3. Examine boundary timing at exactly 300 ms, timer wrap/overflow, clock monotonicity, scheduler latency, relay pickup/dropout, bounce and feedback-settle assumptions. Treat the 20 ms and 25 ms values as preliminary configuration, not released hardware ratings.
4. Prove that boot, reboot, heartbeat restoration, RESET, ARM, configuration load, network recovery, replayed commands and fault acknowledgement cannot create torque or motion.
5. Verify that nominal watchdog loss requires a later physical SR1 RESET and distinct physical SRA1 ARM, and that a fresh validated trajectory after those actions is still required before torque enable.
6. Audit configuration and kinematic hash checks, session binding, command sequence/time checks, start-pose tolerance, joint/TCP/gripper limits, target invalidation and deep-copy/ownership behavior.
7. Identify every mismatch between Python reference behavior and portable C behavior, every unspecified interface, and every condition not covered by tests.
8. Perform FMEA for stuck heartbeat, stuck driver, welded KWD contact, false feedback, shared power/clock/controller/firmware faults, corrupted configuration, process restart and lost communications. Do not assign PL/SIL credit to the ordinary controller or relays.
9. Specify the target compiler/toolchain, warnings, static analysis, coverage, binary reproducibility, GPIO binding, startup pin states, hardware watchdog, Raspberry Pi service isolation, DYNAMIXEL transport, kinematics implementation, logging and disconnected-load HIL evidence needed for the next release.

## Deliverable

Return BLOCKER / MAJOR / MINOR findings with exact file, function, line or requirement references; a corrected patch for any proposed source change; independently reproduced test output; and separate verdicts for source-model review, target compilation, disconnected-load HIL, control-only energization and actuator energization.

Do not mark the design approved or authorize energization.
